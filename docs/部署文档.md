# 智约 · 部署文档（作业三）

> 目标：从一台空服务器开始，按本文步骤部署出可公网访问的管理后台、后端 API、云数据库，并完成 HTTPS、备份和小程序体验版配置。
>
> 适用版本：2026-11-25 的 `main` 分支。密钥一律使用占位符，真实密码只写在服务器 `deploy/.env`，禁止提交仓库。

## 1. 部署架构

```text
微信小程序 ──HTTPS──┐
                    ▼
用户浏览器 ──HTTPS──> Nginx（80/443）
                      ├── /            管理端静态文件（Vue 构建产物）
                      ├── /assets/*    带哈希的静态资源
                      └── /api/*  ──> 后端 Express :3000
                                          │
                                          ▼
                                     MySQL 8.4 :3306
                                     （仅内网/白名单）
```

- 管理端与 API **同域**，`axios baseURL=/api`，不产生跨域。
- Nginx 使用 `try_files` 回退到 `index.html`，刷新 `/bookings` 等子路由不会 404。
- 后端无状态，可水平扩容；签到释放任务由单个实例执行（多实例需加分布式锁，本项目不涉及）。

> **没有云服务器时**：本文的步骤需要一台服务器和备案域名。若暂时都没有，先按 [免费部署方案.md](免费部署方案.md) 用 Render + Aiven/TiDB Cloud + Cloudflare Pages 跑到公网；拿到服务器后再按本文迁移，代码不需要改。注意免费平台子域名不能用于小程序 request 合法域名。

## 2. 准备清单

| 项目 | 要求 | 说明 |
|---|---|---|
| 云服务器 | Ubuntu 22.04/24.04，2 核 2G，系统盘 40G | 安全组只开放 22、80、443 |
| 域名 | 已完成 ICP 备案 | 小程序 request 合法域名必须是备案域名 |
| HTTPS 证书 | Let's Encrypt 或云厂商免费证书 | 有效期与自动续期截图要进上线记录单 |
| MySQL | 服务器内 Docker 容器，或云数据库 | 不对全网开放；仅服务器 IP 白名单 |
| 对象存储 | 阿里云 OSS / 腾讯云 COS / S3 兼容 | 作业三第 6 项，接入方式见第 8 节 |
| 小程序 | 正式 AppID（非测试号） | 体验版上传与成员管理需要 |

## 3. 方案 A：Docker Compose 一键部署（推荐）

仓库已提供 `deploy/`：

```text
deploy/
├── docker-compose.yml          # MySQL + 后端 + Nginx
├── backend.Dockerfile          # 后端生产镜像
├── admin.Dockerfile            # 管理端构建 + Nginx 镜像
├── nginx.conf                  # HTTP 配置：SPA 回退 + /api 反代
├── nginx.https.conf.example    # HTTPS 完整配置示例
├── .env.example                # 生产环境变量模板
└── certbot/www/                # 证书续期验证目录
```

### 3.1 安装 Docker

```bash
sudo apt update
sudo apt install -y git curl
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
newgrp docker
docker --version
docker compose version
```

### 3.2 拉取代码并配置环境变量

```bash
sudo mkdir -p /opt && cd /opt
sudo git clone https://github.com/caikenuan/zhiyue-campus-booking.git zhiyue
sudo chown -R "$USER":"$USER" /opt/zhiyue
cd /opt/zhiyue/deploy

cp .env.example .env
chmod 600 .env
```

编辑 `.env`，**每一项都必须替换**：

```bash
# 生成三个不同的随机串
openssl rand -base64 36
```

```dotenv
MYSQL_ROOT_PASSWORD=<随机串1>
DB_NAME=zhiyue
DB_USER=zhiyue
DB_PASSWORD=<随机串2>
JWT_SECRET=<随机串3，至少32字符>
LLM_BASE_URL=
LLM_API_KEY=
LLM_MODEL=
```

> `.env` 已被 `.gitignore` 忽略。检查：`git check-ignore -v deploy/.env` 应有输出。

### 3.3 启动

```bash
cd /opt/zhiyue/deploy
docker compose up -d --build
docker compose ps
docker compose logs -f backend
```

首次启动时 MySQL 数据卷为空，会自动执行：

1. `database/schema.sql` 建 10 张表；
2. `database/seed.sql` 写入 6 个场地、4 类开放时间、2 个维护窗口、14 条预约（含已完成/已取消/已释放/待审批）。

验证：

```bash
curl -s http://127.0.0.1/api/health
# {"ok":true,"service":"zhiyue-api",...}

curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/
# 200
```

浏览器打开 `http://服务器公网IP/`，用 `admin / admin123` 登录。此时是 HTTP，下一步配域名和证书。

> 重置演示数据：`docker compose down -v && docker compose up -d --build`。`-v` 会删除数据库数据卷，生产环境慎用。

## 4. 域名、HTTPS 与备案

### 4.1 DNS 与备案

1. 域名解析添加 A 记录：`zhiyue.example.com -> 服务器公网 IP`。
2. 在云厂商完成 ICP 备案；未备案域名无法作为小程序合法域名。
3. 安全组放行 80、443。

验证解析：

```bash
dig +short zhiyue.example.com
```

### 4.2 申请证书

```bash
sudo apt install -y certbot
cd /opt/zhiyue/deploy

sudo certbot certonly --webroot \
  -w /opt/zhiyue/deploy/certbot/www \
  -d zhiyue.example.com \
  --email 你的邮箱@example.com \
  --agree-tos --no-eff-email
```

证书路径：`/etc/letsencrypt/live/zhiyue.example.com/{fullchain.pem,privkey.pem}`。

### 4.3 启用 HTTPS

1. 复制示例并替换域名：

```bash
cd /opt/zhiyue/deploy
cp nginx.conf nginx.http.conf.bak
sed 's/zhiyue\.example\.com/你的真实域名/g' nginx.https.conf.example > nginx.conf
```

2. 编辑 `docker-compose.yml` 的 `web` 服务，取消注释：

```yaml
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /etc/letsencrypt:/etc/letsencrypt:ro
```

3. 重启并验证：

```bash
docker compose up -d web
curl -I https://你的域名/
curl -s https://你的域名/api/health
```

4. 自动续期（Let's Encrypt 证书 90 天）：

```bash
sudo certbot renew --dry-run
# 续期后重载 Nginx
echo '0 3 * * * root certbot renew --quiet --deploy-hook "docker compose -f /opt/zhiyue/deploy/docker-compose.yml restart web"' | sudo tee /etc/cron.d/zhiyue-cert
```

截图进上线记录单：`certbot certificates` 输出、浏览器 HTTPS 锁标志、`https://域名/api/health`。

## 5. 云数据库、白名单与备份

### 5.1 使用服务器内 MySQL 容器

`docker-compose.yml` 默认方案，MySQL 不映射宿主端口，只有 `backend` 容器能访问，天然不对公网开放。

检查：

```bash
docker compose ps mysql
# PORTS 一列不应出现 0.0.0.0:3306
ss -lntp | grep 3306 || echo "3306 未对公网监听"
```

### 5.2 使用云数据库（RDS）

1. 创建 MySQL 8.0+ 实例，字符集 `utf8mb4`。
2. 白名单只填**服务器内网 IP**，不要填 `0.0.0.0/0`。
3. 在 `deploy/.env` 把 `DB_HOST/DB_PORT/DB_USER/DB_PASSWORD` 指向云数据库；云库要求 TLS 时加 `DB_SSL=true`。
4. 导入结构和种子数据（不需要 root）：

```bash
# 在 backend/.env 填同样的 DB_* 后执行
cd backend && npm run db:import
```

也可以手动导入：

```bash
mysql -h <云数据库地址> -u zhiyue -p --ssl-mode=REQUIRED zhiyue < database/schema.sql
mysql -h <云数据库地址> -u zhiyue -p --ssl-mode=REQUIRED zhiyue < database/seed.sql
```

5. 如果用 `backend/scripts/init-db.js` 初始化，设置 `DB_USER_HOSTS` 为服务器固定 IP，避免 `%` 全网授权：

```dotenv
DB_USER_HOSTS=10.0.0.5
```

### 5.3 每日备份

Docker 方案（在宿主机 crontab）：

```bash
sudo mkdir -p /opt/backup/zhiyue
sudo tee /opt/backup/zhiyue/backup.sh >/dev/null <<'SH'
#!/usr/bin/env bash
set -euo pipefail
STAMP=$(date +%F-%H%M)
docker exec zhiyue-mysql-1 sh -c \
  'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines zhiyue' \
  | gzip > "/opt/backup/zhiyue/zhiyue-$STAMP.sql.gz"
find /opt/backup/zhiyue -name '*.sql.gz' -mtime +7 -delete
SH
sudo chmod +x /opt/backup/zhiyue/backup.sh
sudo /opt/backup/zhiyue/backup.sh
ls -lh /opt/backup/zhiyue/
```

```bash
# 每天 02:30
echo '30 2 * * * root /opt/backup/zhiyue/backup.sh >> /var/log/zhiyue-backup.log 2>&1' | sudo tee /etc/cron.d/zhiyue-backup
```

> 容器名以 `docker compose ps` 实际输出为准（默认 `zhiyue-mysql-1`）。截图：备份文件列表、cron 配置、恢复演练结果。

## 6. 方案 B：不用 Docker（PM2 + 宿主 Nginx）

适合已装 MySQL 的服务器。

```bash
# 1. 后端
cd /opt/zhiyue/backend
cp .env.example .env && chmod 600 .env
# 编辑 .env：JWT_SECRET、DB_*、DB_USER_HOSTS=%
npm ci --omit=dev
npm run db:init

sudo npm i -g pm2
pm2 start src/server.js --name zhiyue-api
pm2 save
pm2 startup systemd   # 按提示执行输出的命令
pm2 logs zhiyue-api --lines 50

# 2. 管理端
cd /opt/zhiyue/frontend/admin
npm ci
npm run build
sudo mkdir -p /var/www/zhiyue
sudo cp -r dist/* /var/www/zhiyue/

# 3. Nginx
sudo apt install -y nginx
sudo cp /opt/zhiyue/deploy/nginx.conf /etc/nginx/conf.d/zhiyue.conf
sudo sed -i 's#server backend:3000;#server 127.0.0.1:3000;#' /etc/nginx/conf.d/zhiyue.conf
sudo sed -i 's#root /usr/share/nginx/html;#root /var/www/zhiyue;#' /etc/nginx/conf.d/zhiyue.conf
sudo nginx -t && sudo systemctl reload nginx
```

后端日志按日期切分：

```bash
pm2 install pm2-logrotate
pm2 set pm2-logrotate:retain 7
pm2 set pm2-logrotate:dateFormat YYYY-MM-DD
```

## 8. 对象存储（作业三第 6 项）

> **当前状态：上传功能已实现并通过自动化测试；尚未接入真实云对象存储。** 当前默认 `local` 驱动把图片写到服务器数据卷，适合本地/演示；作业三要求的“云服务对象存储”必须配置 `STORAGE_DRIVER=s3` 后重新验收，未实际接入前记录单第 6 段不得勾选“是”。

### 8.1 已实现的接口

| 项 | 内容 |
|---|---|
| 接口 | `POST /api/uploads`，`multipart/form-data`，字段名 `file` |
| 权限 | 已登录用户（学生签到照片、管理员场地图片） |
| 限制 | 仅 jpg/png/webp/gif，≤5 MB，单次 1 张 |
| 响应 | `201 { url, key, driver, contentType, size }` |
| 存储 | 数据库只存 URL：`resources.image_url`、`checkins.photo_url` |
| 页面 | 管理端“场地与时段”新增/编辑可上传图片；小程序列表/详情展示场地图片；签到页支持“拍照签到” |
| 驱动 | `local`（默认）或 `s3`（S3 兼容对象存储） |

自动化用例：`backend/tests/uploads.test.js` 的 U-01—U-04（未登录 401、PNG 上传可访问、非图片拒绝、超过 5 MB 拒绝），合并后共 **55 项测试全部通过**。

### 8.2 本地驱动（当前默认）

```dotenv
STORAGE_DRIVER=local
STORAGE_LOCAL_DIR=uploads
```

- 文件写入 `backend/uploads/`（Docker 中挂载 `uploads_data` 数据卷）；
- 通过 `GET /uploads/...` 访问；
- 数据库只存 URL，验证方式：

```bash
mysql -u zhiyue -p zhiyue -e "SELECT id,name,image_url FROM resources LIMIT 3;"
# image_url 应为 http(s)://.../uploads/images/...
```

### 8.3 接入云对象存储（S3 兼容）

| 厂商 | Endpoint | Region | 公开访问 |
|---|---|---|---|
| 腾讯云 COS | `https://cos.<地域>.myqcloud.com` | 地域，如 `ap-guangzhou` | Bucket 公共读，或绑定 CDN 域名 |
| Cloudflare R2 | `https://<account>.r2.cloudflarestorage.com` | `auto` | 绑定自定义域名或 r2.dev |
| MinIO | `https://minio.example.com` | `us-east-1` | Bucket 公共读 |
| 阿里云 OSS | 以 OSS 的 S3 兼容 Endpoint 文档为准 | 地域 | Bucket 公共读 |

```dotenv
STORAGE_DRIVER=s3
STORAGE_ENDPOINT=https://cos.ap-guangzhou.myqcloud.com
STORAGE_REGION=ap-guangzhou
STORAGE_BUCKET=zhiyue-images-1250000000
STORAGE_ACCESS_KEY=<占位符>
STORAGE_SECRET_KEY=<占位符>
STORAGE_PUBLIC_BASE_URL=https://zhiyue-images-1250000000.cos.ap-guangzhou.myqcloud.com
```

修改后重启后端：

```bash
docker compose up -d backend
```

> AccessKey 只写服务器 `.env`，建议使用只允许该 Bucket 读写的子账号；Bucket 公共读时禁止上传 HTML/SVG 等可执行内容，后端已限制为图片 MIME。

### 8.4 验收

1. 管理端场地表单上传 1 张图片，返回 `https://...` URL；
2. 无痕窗口打开 URL，图片可访问且 Content-Type 为图片；
3. 数据库 `resources.image_url` / `checkins.photo_url` 只有 URL，无 BLOB；
4. 小程序“拍照签到”上传成功，`checkins.photo_url` 有值；
5. 关闭外网或清空 AccessKey 后上传失败不影响预约主流程；
6. 截图进上线记录单图 12、图 13。

### 8.5 已有数据库升级

旧库需要补两个字段（新库执行 `schema.sql` 时已包含）：

## 12. 上线自检六问

1. 评审老师用手机扫码，能不能进？——体验版二维码 + 非成员实测。
2. 学生账号能否看到别人的手机号？——用户表无手机号字段，接口不返回他人隐私。
3. 关掉 AI 服务，预约还能不能走完？——`LLM_*` 留空即回退规则解析。
4. 数据库是否对全网开放？——`ss -lntp`、安全组、RDS 白名单三重确认。
5. 换一台空服务器照文档能否装起来？——按本文第 3 节复跑并记录耗时。
6. 仓库有没有密码/密钥——`git grep -nE "password|secret|access_key|token"` + Git 历史扫描。

## 13. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器启动后 `/api/health` 503 | 数据库未就绪或密码不一致 | `docker compose logs mysql backend`；核对 `.env` |
| 登录 401 | JWT_SECRET 变更导致旧 token 失效 | 重新登录 |
| 刷新子路由 404 | Nginx 缺少 `try_files` | 用仓库 `deploy/nginx.conf` |
| 跨域报错 | 前端请求了绝对地址 | 管理端保持 `baseURL=/api`，走同域反代 |
| 证书申请失败 | 80 端口未放行/DNS 未生效/域名未备案 | `dig`、安全组、备案状态逐项排查 |
| 小程序提示合法域名错误 | 域名未备案或用了 HTTP/IP | 配置 HTTPS 备案域名 |
| MySQL 容器反复重启 | 数据卷残留旧密码 | 确认可清空后 `docker compose down -v` |
| 时区差 8 小时 | 容器时区不对 | 确认 `TZ=Asia/Shanghai`、MySQL `--default-time-zone=+08:00` |

- [ ] `https://域名/api/health` 返回 `ok:true`
- [ ] 三角色账号可登录，权限符合矩阵
- [ ] 刷新 `/bookings`、`/stats`、`/logs` 不 404
- [ ] 小程序体验版二维码可被非成员扫码打开
- [ ] 数据库不对公网开放，白名单仅服务器 IP
- [ ] 每日备份已生成并做过一次恢复演练
- [ ] 对象存储上传返回可访问 URL，数据库无二进制
- [ ] `deploy/.env`、服务器证书私钥未进 Git
- [ ] 上线记录单六段全部勾选并附图
