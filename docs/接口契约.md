# 智约 · 接口契约（签到 / 信用 / 后台运营）

> 版本：S2 验收版（2026-11-22）
> 适用代码：`backend/src/routes/bookings.js`、`credit.js`、`admin.js`，`backend/src/services/booking.js`、`credit.js`、`scheduler.js`
> 基础地址：本地 `http://localhost:3000/api`
> 认证方式：`Authorization: Bearer <JWT>`，除登录外均需登录
> 时间格式：请求 `YYYY-MM-DD HH:mm`；响应 DATETIME 为 `YYYY-MM-DD HH:mm:ss`（MySQL 连接使用 `dateStrings`）

## 1. 通用约定

### 1.1 响应格式

成功响应直接返回业务对象，例如：

```json
{ "booking": { "id": 12, "status": "CHECKED_IN" } }
```

失败响应统一为：

```json
{ "error": { "code": "INVALID_STATE", "message": "当前预约状态不能签到", "details": null } }
```

### 1.2 字段命名

- 预约、签到相关接口由 `mapBooking` 输出 **camelCase**：`startAt`、`endAt`、`resourceId`、`checkedInAt`、`qrToken` 等。
- 管理端用户/日志/爽约/申诉列表以及信用记录直接输出数据库字段，使用 **snake_case**：`student_no`、`credit_score`、`created_at`、`resource_id` 等。
- 前端已按各自接口适配。新增接口时应先确认命名，避免同一页面混用。

### 1.3 角色

| 值 | 含义 |
|---|---|
| `STUDENT` | 学生 |
| `VENUE_ADMIN` | 场地管理员，数据范围为 `resource_managers` 中分配的场地（种子数据为 1—3 号） |
| `COLLEGE_ADMIN` | 学院管理员，可看全部数据 |

### 1.4 状态枚举

| 枚举 | 值 |
|---|---|
| 预约状态 | `PENDING`、`CHECKED_IN`、`COMPLETED`、`CANCELLED`、`RELEASED`、`PENDING_APPROVAL`、`REJECTED` |
| 签到方式 | `QR`、`ASSISTED` |
| 信用记录类型 | `NO_SHOW`、`APPEAL_REVOKE`、`MANUAL` |
| 信用记录状态 | `VALID`、`REVOKED` |
| 申诉状态 | `PENDING`、`APPROVED`、`REJECTED` |

## 2. 认证

- 请求：`{ "studentNo": "admin", "password": "admin123" }`
- 成功 200：

```json
{
  "token": "<jwt>",
  "user": {
    "id": 1,
    "studentNo": "admin",
    "name": "学院管理员",
    "role": "COLLEGE_ADMIN",
    "status": "ACTIVE",
    "creditScore": 100,
    "suspendedUntil": null
  }
}
```

- 错误：401 `UNAUTHORIZED`（账号或密码错误）；403 `FORBIDDEN`（账号已停用）

### GET `/api/auth/me`

- 权限：已登录
- 成功 200：`{ "user": { ...同 login.user } }`
- 错误：401 `UNAUTHORIZED`

## 3. 签到接口

### 3.1 POST `/api/bookings/checkin`（扫码签到）

- 权限：已登录；签到码对应预约的本人，或学院管理员
- 请求：

```json
{ "qrToken": "demo-qr-token-0001" }
```

- 成功 200：`{ "booking": { ...签到后的预约，status=CHECKED_IN } }`
- 校验顺序：签到码存在 → 归属/角色 → 状态不是 `RELEASED` → 状态必须 `PENDING` → 未到开始时间拒绝 → 超过开始后 15 分钟拒绝
- 错误：

| HTTP | code | 场景 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 缺少 `qrToken` |
| 401 | `UNAUTHORIZED` | 未登录或 token 过期 |
| 403 | `FORBIDDEN` | 不是本人预约，且不是学院管理员 |
| 404 | `INVALID_QR` | 签到码无效或预约不存在 |
| 409 | `INVALID_STATE` | 已释放、已取消、已签到、未到开始时间、状态已变化 |
| 409 | `CHECKIN_EXPIRED` | 已超过开始后 15 分钟 |

### 3.2 POST `/api/bookings/:id/checkin`（预约详情自助签到）

- 权限：本人；学院管理员也可调用
- 请求：无 body（`{}` 即可）
- 成功 200：`{ "booking": { ... } }`，`status=CHECKED_IN`，写入 `checkins(method='QR', operator_id=NULL)`
- 错误：同 3.1；预约不存在返回 404 `INVALID_QR`

### 3.3 POST `/api/admin/bookings/:id/assisted-checkin`（管理员辅助签到）

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`（路由级）；场地管理员只能操作自己负责场地的预约
- 请求：无 body
- 成功 200：`{ "booking": { ... } }`，`status=CHECKED_IN`，写入 `checkins(method='ASSISTED', operator_id=操作人)`，并写操作日志 `BOOKING_ASSISTED_CHECKIN`
- 错误：

| HTTP | code | 场景 |
|---|---|---|
| 401 | `UNAUTHORIZED` | 未登录 |
| 403 | `FORBIDDEN` | 学生调用；场地管理员越界；非本场地 |
| 404 | `NOT_FOUND` / `INVALID_QR` | 预约不存在 |
| 409 | `INVALID_STATE` | 开始前、已释放、已取消、已签到 |
| 409 | `CHECKIN_EXPIRED` | 超过开始后 15 分钟 |

> 签到时间窗：`start_at <= NOW() <= start_at + 15 分钟`。开始前和超时后都不能签到；已释放只能申诉。

## 4. 信用与申诉接口

### 4.1 GET `/api/credit/me`

- 权限：已登录（学生本人）
- 成功 200：

```json
{
  "user": {
    "id": 5,
    "studentNo": "2024000001",
    "name": "测试学生",
    "creditScore": 90,
    "suspendedUntil": null
  },
  "noShowCount": 1,
  "noShowLimit": 3,
  "windowDays": 30,
  "suspensionDays": 7,
  "records": [
    {
      "id": 1,
      "type": "NO_SHOW",
      "status": "VALID",
      "occurred_at": "2026-11-19 09:15:00",
      "note": "超时未签到（演示数据）",
      "booking_id": null,
      "start_at": null,
      "end_at": null,
      "resource_name": null
    }
  ]
}
```

- 说明：`noShowCount` 只统计近 30 天 `status='VALID'` 的 `NO_SHOW`；`records` 最多 50 条，按发生时间倒序。
- 错误：401 `UNAUTHORIZED`；404 `NOT_FOUND`（用户不存在）

### 4.2 GET `/api/credit/appeals`

- 权限：已登录
  - 学生：只看自己的申诉
  - 场地管理员：只看自己负责场地预约的申诉
  - 学院管理员：看全部
- 成功 200：`{ "items": [ ... ] }`
- 列表字段（snake_case）：`id`、`booking_id`、`user_id`、`reason`、`status`、`result`、`created_at`、`handled_at`、`student_name`、`student_no`、`start_at`、`end_at`、`resource_name`、`resource_id`
- 错误：401 `UNAUTHORIZED`；403 `FORBIDDEN`（角色不允许）

### 4.3 POST `/api/credit/appeals`

- 权限：已登录；只能为自己的预约申诉
- 请求：

```json
{ "bookingId": 3, "reason": "临时被导师叫走，未能按时到场签到" }
```

- 校验：`bookingId` 正整数；`reason` 去空格后 5—1000 字
- 成功 201：

```json
{ "appeal": { "id": 1, "bookingId": 3, "status": "PENDING" } }
```

- 业务校验：预约存在 → 属于本人 → 状态必须 `RELEASED` → 该预约不能已有 `PENDING` 申诉
- 错误：

| HTTP | code | 场景 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 理由少于 5 字、bookingId 非法 |
| 401 | `UNAUTHORIZED` | 未登录 |
| 403 | `FORBIDDEN` | 不是本人预约 |
| 404 | `NOT_FOUND` | 预约不存在 |
| 409 | `INVALID_STATE` | 预约不是 `RELEASED` |
| 409 | `CONFLICT` | 已有待处理申诉 |

## 5. 管理端接口

> 以下接口均先经过 `authRequired` + `requireRole('VENUE_ADMIN','COLLEGE_ADMIN')`，除非单独标注。

### 5.1 GET `/api/admin/dashboard`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`
- 请求：无
- 成功 200：

```json
{
  "stats": {
    "todayBookings": 2,
    "pendingCheckin": 0,
    "releasedToday": 1,
    "activeResources": 6,
    "suspendedUsers": 0
  },
  "recentBookings": [
    {
      "id": 2,
      "start_at": "2026-11-22 21:35:00",
      "end_at": "2026-11-22 22:05:00",
      "status": "CHECKED_IN",
      "user_name": "蔡珂暖",
      "resource_name": "自习区 B-101"
    }
  ]
}
```

- 数据范围：场地管理员的 `todayBookings`、`pendingCheckin`、`releasedToday`、`activeResources` 只统计自己负责的场地；`suspendedUsers` 是全局停权人数（停权不绑定场地）。
- 错误：401、403

### 5.2 GET `/api/admin/bookings`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`
- 查询参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| `status` | string | 预约状态，如 `PENDING` |
| `resourceId` | number | 场地 ID |
| `date` | `YYYY-MM-DD` | 按开始日期筛选 |
| `userId` | number | 学生用户 ID |

- 成功 200：`{ "items": [ mapBooking... ] }`，按开始时间倒序，最多 200 条
- 数据范围：场地管理员自动追加 `resource_id IN (负责场地)`；越界查询返回空数组，不会报 403。
- 错误：401、403

### 5.3 POST `/api/admin/bookings/:id/review`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`；场地管理员需在负责范围内
- 请求：

```json
{ "decision": "APPROVE", "reason": "同意" }
```

`decision` 只能是 `APPROVE` 或 `REJECT`；`reason` 最长 255。
- 成功 200：`{ "booking": { ... } }`
  - `APPROVE`：`PENDING_APPROVAL → PENDING`
  - `REJECT`：`PENDING_APPROVAL → REJECTED`，删除 `booking_slots`，释放时段
- 错误：400 `VALIDATION_ERROR`；403 `FORBIDDEN`；404 `NOT_FOUND`；409 `INVALID_STATE`（不是待审批）

### 5.4 GET `/api/admin/users`

- 权限：仅 `COLLEGE_ADMIN`
- 查询参数：`role`（`STUDENT`/`VENUE_ADMIN`/`COLLEGE_ADMIN`）、`keyword`（学号或姓名模糊）
- 成功 200：`{ "items": [ { id, student_no, name, role, status, credit_score, suspended_until, created_at } ] }`，最多 200 条
- 错误：401、403

### 5.5 PATCH `/api/admin/users/:id`

- 权限：仅 `COLLEGE_ADMIN`
- 请求（至少一个字段）：

```json
{ "name": "新姓名", "role": "VENUE_ADMIN", "status": "DISABLED" }
```

- 成功 200：`{ "user": { id, student_no, name, role, status, credit_score, suspended_until } }`
- 限制：不能修改自己的角色或状态（400 `VALIDATION_ERROR`）；写操作日志 `USER_UPDATED`
- 错误：400、403、404

### 5.6 GET `/api/admin/no-shows`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`
- 成功 200：`{ "items": [ { id, student_no, name, credit_score, suspended_until, no_show_count, last_no_show_at } ] }`
- 数据范围：场地管理员只统计与自己负责场地预约关联的爽约记录；学院管理员统计全部
- 只读：没有 POST/PUT/DELETE 路由；写请求返回 404
- 错误：401、403

### 5.7 GET `/api/admin/stats/utilization`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`
- 查询参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `from` | 今天 - 6 天 | 开始日期，包含 |
| `to` | 今天 | 结束日期，**包含当天** |

- 成功 200：

```json
{
  "from": "2026-11-23",
  "to": "2026-11-23",
  "items": [
    {
      "resourceId": 6,
      "resourceName": "羽毛球场 1 号",
      "type": "SPORTS",
      "days": 1,
      "capacityMinutes": 780,
      "bookedMinutes": 60,
      "bookingCount": 1,
      "utilizationRate": 0.0769
    }
  ]
}
```

- 计算规则：
  - 只统计 `PENDING`、`CHECKED_IN`、`COMPLETED`，排除 `CANCELLED`、`RELEASED`、`REJECTED`
  - `days = to - from + 1`（自然日，首尾都算）
  - `capacityMinutes = 每天开放分钟数 × days`
  - `utilizationRate = bookedMinutes / capacityMinutes`，保留 4 位小数
  - 场地管理员只返回负责场地
- 错误：400 `VALIDATION_ERROR`（日期格式错误或 from > to）；401；403

### 5.8 GET `/api/admin/logs`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`
- 查询参数：`limit`，默认 100，范围 1—500
- 成功 200：`{ "items": [ { id, actor_id, actor_name, action, target_type, target_id, resource_id, resource_name, detail, created_at } ] }`
- 数据范围：场地管理员只看 `resource_id` 属于自己负责场地，或操作人是自己的日志
- 只读：没有修改/删除路由；写请求返回 404
- 常见 action：`BOOKING_CREATED`、`BOOKING_CANCELLED`、`BOOKING_CHECKIN`、`BOOKING_ASSISTED_CHECKIN`、`BOOKING_NO_SHOW`、`BOOKING_COMPLETED`、`BOOKING_APPROVED`、`BOOKING_REJECTED`、`CREDIT_NO_SHOW_REVOKED`、`APPEAL_REJECTED`、`USER_UPDATED`
- 错误：401、403

### 5.9 GET `/api/admin/appeals`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`
- 成功 200：`{ "items": [ ...同 4.2 列表字段... ] }`
- 数据范围：场地管理员只看负责场地；学院管理员全部
- 错误：401、403

### 5.10 POST `/api/admin/appeals/:id/handle`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`；场地管理员需在负责范围内
- 请求：

```json
{ "decision": "APPROVED", "result": "情况属实，撤销本次爽约" }
```

`decision` 只能是 `APPROVED` 或 `REJECTED`；`result` 最长 255。
- 成功 200：`{ "appeal": { "id": 1, "status": "APPROVED" } }`
- 通过 `APPROVED` 的效果：
  1. 对应 `credit_records.status` 改为 `REVOKED`
  2. 用户信用分 `+10`，上限 100
  3. 重新统计近 30 天有效爽约；不足 3 次则清空 `suspended_until`
  4. 写操作日志 `CREDIT_NO_SHOW_REVOKED`
- 驳回 `REJECTED` 的效果：申诉状态改为 `REJECTED`，写日志 `APPEAL_REJECTED`，信用记录不变
- 错误：400、401、403、404 `NOT_FOUND`、409 `INVALID_STATE`（已处理）

### 5.11 GET `/api/admin/scheduler/status`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`
- 成功 200：`{ "toRelease": 0, "toComplete": 0 }`
- 说明：分别统计“已开始超过 15 分钟仍 PENDING”和“已签到且已到结束时间”的预约数

### 5.12 POST `/api/admin/scheduler/run`

- 权限：仅 `COLLEGE_ADMIN`
- 请求：无
- 成功 200：`{ "released": [3], "completed": [] }`
- 效果：执行一次 `releaseExpiredBookings` + `completeFinishedBookings`；释放会记爽约、扣分、必要时停权；重复执行幂等
- 错误：401、403

### 5.13 GET `/api/admin/resources`

- 权限：`VENUE_ADMIN`、`COLLEGE_ADMIN`
- 成功 200：`{ "items": [ mapResource... ] }`
- 数据范围：场地管理员只返回负责的 1—3 号场地；用于预约页的场地下拉框
- 说明：该接口的增删改属于场地管理模块（蔡珂暖负责），场地管理员越界修改返回 403

## 6. 错误码

| code | 典型 HTTP | 含义 |
|---|---|---|
| `VALIDATION_ERROR` | 400 | 参数格式/取值范围错误 |
| `UNAUTHORIZED` | 401 | 未登录、token 过期、账号密码错误 |
| `FORBIDDEN` | 403 | 角色不允许、越权、账号停用 |
| `NOT_FOUND` | 404 | 资源不存在 |
| `CONFLICT` | 409 | 通用冲突（如已有待处理申诉） |
| `GRANULARITY_INVALID` | 400 | 不是 30 分钟整数倍 |
| `DURATION_EXCEEDED` | 400 | 单笔超过 4 小时 |
| `BOOKING_WINDOW_INVALID` | 400 | 过去时段、超过明天、超出开放时间 |
| `CROSS_DAY_INVALID` | 400 | 跨天 |
| `SLOT_CONFLICT` | 409 | 时段已被占用 |
| `MAINTENANCE_WINDOW` | 409 | 维护时段 |
| `USER_SUSPENDED` | 403 | 停权期内下单 |
| `CHECKIN_EXPIRED` | 409 | 超过开始后 15 分钟 |
| `INVALID_QR` | 404 | 签到码无效或预约不存在 |
| `INVALID_STATE` | 409 | 当前状态不允许该操作 |
| `RESOURCE_CLOSED` | 409 | 场地未开放 |
| `INTERNAL_ERROR` | 500 | 未捕获异常（错误中间件） |

## 7. 关键业务参数

| 参数 | 值 | 代码位置 |
|---|---|---|
| 预约粒度 | 30 分钟 | `RULES.slotMinutes` |
| 单笔最长 | 240 分钟 | `RULES.maxBookingMinutes` |
| 可预约日期 | 今天、明天 | `RULES.advanceDays = 1` |
| 签到窗口 | 开始后 0—15 分钟 | `RULES.checkinGraceMinutes = 15` |
| 爽约统计窗口 | 近 30 天 | `RULES.noShowWindowDays = 30` |
| 停权阈值 | 3 次 | `RULES.noShowLimit = 3` |
| 停权时长 | 7 天 | `RULES.suspensionDays = 7` |
| 定时任务间隔 | 30 秒 | `scheduler.startScheduler(30_000)` |
