## 6. 部署路线决策

### 路线 A：免费国外服务（原计划）

Aiven（MySQL）+ Render（后端）+ Cloudflare Pages（管理端）+ B2/R2（图片）。

- 优点：不花钱。
- 当前障碍：注册页访问不稳定；Render 注册依赖 GitHub/Google，而这两个都超时。
- 若热点能打开 GitHub：优先走这条。
- 若 Aiven 仍打不开：换 TiDB Cloud Starter；数据库导入仍用 `npm run db:import`。

### 路线 B：朋友已购买的云服务器（正在评估）

技术上可行，但必须朋友明确同意，并约定使用期限。影响与隔离要求：

- 朋友有 root，能看到数据库和上传文件 → 只放演示数据。
- 可能与朋友现有网站/MySQL/Nginx 冲突 → 用独立目录 `/opt/zhiyue`、独立 Compose 项目名、独立数据库、独立 Linux 用户。
- 80/443 被占用 → 先用 8080，或 Nginx `server_name` 区分。
- 服务器在国内时，`git clone GitHub` 也可能失败 → **打包上传代码**，npm 用国内镜像，Docker 配国内镜像源。
- 不要让朋友在群里发 root 密码 → 建单独账号 + SSH 公钥，或临时密码，部署后改掉。
- 作业记录要真实；如果课程要求“本人云账号”，先问老师。

**需要朋友提供：**

1. 国内还是海外？
2. Ubuntu / Debian / CentOS 版本？
3. 是否已装 Docker + Docker Compose？
4. 80、443 是否空闲？有无现有网站？
5. 公网 IP？
6. SSH 方式：单独账号 + 公钥，或临时密码？
7. 有无已备案域名？
8. 能用到什么时候？

### 路线 C：临时公网隧道（兜底）

用 SSH 隧道把本机后台临时暴露成 HTTPS 地址。不花钱、当天可用，但电脑必须常开、数据库在本机、地址不固定，只能演示，不算正式云部署。

### 路线 D：国内学生云服务器（最稳）

阿里云/腾讯云学生机，约十几元/月，需实名。用 `IP.sslip.io` + Let's Encrypt 可获得 HTTPS（不需要买域名），但**不是备案域名**，小程序体验版仍做不了。
