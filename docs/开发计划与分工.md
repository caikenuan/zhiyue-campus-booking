## 1. 规则基线（已确认，不得擅自更改）

| 参数 | 本组取值 | 实现要点 |
|---|---|---|
| 最小预约粒度 | 30 分钟 | 起止时间必须是 30 分钟整数倍 |
| 单次最长时长 | 4 小时 | 每笔预约单独校验；续约另计 |
| 相邻时段 | 允许紧邻 | 半开区间，冲突判定 `start_at < existing_end AND end_at > existing_start` |
| 提前预约窗口 | 1 天 | 按自然日，仅可约今天和明天 |
| 未签到自动释放 | 15 分钟 | 开始后 15 分钟未签到，定时任务置为 `RELEASED` 并计爽约 |
| 爽约停权 | 3 次停 7 天 | 近 30 天累计 3 次，停权期内禁止下单 |

补充规则：禁止跨天；维护时段禁止预约；同一场地不得重叠但可首尾相接；续约后每笔仍不超过 4 小时；管理员可辅助签到，但预约已自动释放的不得补记正常签到，只能走异常申诉（C-09）。

> 注意：PPT 第 13 页的“规则卡 No.17”示例参数（20 分钟/3 小时/间隔 15 分钟等）与本组签字确认单不同。开发一律以签字确认单和《需求说明书》为准，答辩前需向老师确认该页只是示例。

## 2. 课程硬性验收（来自 PPT）

1. **跑得起来**：公有云地址答辩当天可直接访问，换陌生手机扫码也能进。
2. **说得清楚**：从仓库随机抽 3 个函数，5 分钟内讲清输入、边界、异常分支。
3. **留得下证据**：干净机器照 README 半小时内可运行；Git 记录能看出谁在哪周做了什么。
4. 27 条验收用例（老师要求 22 条 + 本组续约/辅助签到 5 条），含 **10 并发只成功 1 单**。
5. 实践报告必须含“AI 帮倒忙”案例：原始提示词、AI 回答、发现过程、改前改后 diff。
6. 交付物：源代码、需求说明书、项目进度计划、实践报告、线上地址。
7. 评分权重：功能完整 30%、技术正确 30%、代码可解释 20%、工程规范 12%、报告复盘 8%。

## 3. 技术方案（建议，待确认）

| 层 | 选型 | 理由 |
|---|---|---|
| 小程序 | 微信小程序原生 | 构建链短，便于现场解释和真机演示 |
| 管理后台 | Vue 3 + Element Plus + Vite + Pinia + Axios | 与课程要求一致，AI 生成效率高 |
| 后端 | Node.js 20 + Express + mysql2 + Zod + JWT | 代码直白、并发和事务可手写，便于答辩解释 |
| 数据库 | MySQL 8.0 | 事务、唯一索引、行锁满足并发预约 |
| 部署 | 本地运行 + 微信开发者工具演示 | 暂不购买云服务器；开发者工具中勾选“不校验合法域名”访问 `http://localhost:3000` |
| AI 助手 | LLM 只做意图解析，可用性由 SQL 判定 | 模型不读数据库，失败时回退普通表单；按 PPT 作为必做项，蔡珂暖主责 |

> 不建议使用重型 ORM 自动生成冲突逻辑；预约冲突和并发必须能逐行讲清。
>
> **未上云的风险**：PPT 把“公有云地址答辩当天可访问”列为硬门槛。当前阶段先按本地演示推进；后期可用学生机/免费额度补一个线上地址，或提前向老师说明演示方式。不能把“本地能跑”当成“已经满足线上验收”。

## 4. 协作规则

- `main` 只放已联调、可运行的内容；所有开发从 `main` 拉功能分支，通过 PR 合并。
- 每个 PR 至少由另一人 review；不允许直接 push `main`。
- 提交信息使用 `feat:`、`fix:`、`test:`、`docs:` 前缀，提交内容按模块拆分。
- 接口先行：先冻结接口和数据库字段，再并行开发；前端在后端未完成时先用 mock 数据。
- 每人必须同时有前端和后端提交，不能一人只写页面、一人只写接口。
- 每日 15 分钟同步：昨天完成、今天计划、当前阻塞。
- 密码、密钥、数据库真实账号只放本地 `.env`，仓库只提交 `.env.example`。
- 完成定义（DoD）：代码 + 自测 + 接口文档 + 页面可演示 + 另一人 review。

## 6. 并行开发顺序

### 第 0 阶段：契约与脚手架（第 1 天，两人同时）

共同完成（约 2 小时）：

1. 冻结数据库表、字段、状态枚举。
2. 冻结接口路径、请求/响应格式、错误码。
3. 冻结三角色权限矩阵。
4. 确认分支、目录、环境变量模板。

并行任务：

- 蔡珂暖：`backend/` Express 骨架、数据库连接、迁移脚本、种子数据、统一错误处理。
- 史曼琪：`frontend/admin/` Vue 3 骨架、登录/布局/路由、Axios 封装；`frontend/mini-program/` 小程序骨架、TabBar、请求工具。

当天各自合并到 `main`，保证第二天两人都能拉到完整骨架。

### 第 1 阶段：最小闭环（第 2—3 天）

目标：跑通“查空档 → 下单 → 扫码签到 → 超时自动释放 → 信用记录”一条链路。

- 蔡珂暖：空闲时段查询 API + 预约创建/取消 API + 小程序查询/下单页。
- 史曼琪：签到 API + 定时释放任务 + 信用记录 API + 小程序签到/信用页。
- 两人用种子数据联调，先不追求管理端全部页面。

### 第 2 阶段：完整模块（第 4—10 天）

- 蔡珂暖：我的预约、续约、管理端场地与时段、AI 找位助手。
- 史曼琪：管理端审批/辅助签到、用户与角色、爽约名单、利用率统计、操作日志、申诉处理。
- 每完成一个模块立即提 PR，不攒大提交。

### 第 3 阶段：集成与本地演示（第 11—14 天）

- 前后端联调、权限回归、27 条用例、10 并发压测。
- 本地 MySQL 启动脚本、后端启动脚本、管理后台启动脚本。
- 微信开发者工具导入小程序，勾选“不校验合法域名”，真机预览演示。
- README 改为经过实际验证的命令，补运行截图。
- 若后续拿到云资源，再补 Nginx + HTTPS + 线上地址；当前不阻塞开发。

### 第 4 阶段：验收与报告（第 15—18 天）

- 代码解释抽签演练：每人能讲清自己和他人的核心函数。
- 实践报告：含 AI 帮倒忙案例、计划 vs 实际、个人贡献。

## 8. 数据模型与接口草案

### 核心表

| 表 | 关键字段 |
|---|---|
| `users` | `id`、`student_no`、`name`、`password_hash`、`role`（STUDENT/VENUE_ADMIN/COLLEGE_ADMIN）、`status`、`suspended_until` |
| `resources` | `id`、`name`、`type`、`building`、`room`、`capacity`、`open_from`、`open_to`、`status` |
| `resource_managers` | `resource_id`、`user_id`（场地管理员数据范围） |
| `maintenance_windows` | `id`、`resource_id`、`start_at`、`end_at`、`reason` |
| `bookings` | `id`、`user_id`、`resource_id`、`start_at`、`end_at`、`status`、`checked_in_at`、`cancel_reason`、`created_at` |
| `booking_slots` | `resource_id`、`slot_start`、`booking_id`，唯一键 `(resource_id, slot_start)` |
| `checkins` | `id`、`booking_id`、`method`（QR/ASSISTED）、`operator_id`、`checked_in_at` |
| `credit_records` | `id`、`user_id`、`booking_id`、`type`、`occurred_at`、`note` |
| `appeals` | `id`、`booking_id`、`user_id`、`reason`、`status`、`handled_by`、`result` |
| `operation_logs` | `id`、`actor_id`、`action`、`target_type`、`target_id`、`detail`、`created_at` |

### 状态机

```text
PENDING ──签到──> CHECKED_IN ──结束──> COMPLETED
   │
   ├──用户取消──> CANCELLED
   └──超时未签到──> RELEASED（计一次爽约）

PENDING_APPROVAL ──管理员通过──> PENDING
                 └──管理员驳回──> REJECTED
```

### 接口前缀

- 认证：`POST /api/auth/login`、`GET /api/auth/me`
- 场地：`GET /api/resources`、`GET /api/resources/:id`、`GET /api/resources/:id/availability`
- 预约：`POST /api/bookings`、`GET /api/bookings/mine`、`POST /api/bookings/:id/cancel`、`POST /api/bookings/:id/renew`
- 签到：`POST /api/bookings/:id/checkin`、`POST /api/admin/bookings/:id/assisted-checkin`
- 信用：`GET /api/credit/me`、`POST /api/appeals`
- 管理：`/api/admin/bookings`、`/api/admin/users`、`/api/admin/no-shows`、`/api/admin/stats/utilization`、`/api/admin/logs`

### 统一错误码

`GRANULARITY_INVALID`、`DURATION_EXCEEDED`、`BOOKING_WINDOW_INVALID`、`CROSS_DAY_INVALID`、`SLOT_CONFLICT`、`MAINTENANCE_WINDOW`、`USER_SUSPENDED`、`CHECKIN_EXPIRED`、`INVALID_QR`、`FORBIDDEN`、`NOT_FOUND`。
