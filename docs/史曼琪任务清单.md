## 2. 第一天：把项目跑起来

### 2.1 前置条件

- Windows 10/11，已安装 Node.js 18+（推荐 24.x）和 Git
- 已接受 GitHub 仓库的协作者邀请（否则 push 会 403）
- 微信开发者工具已安装并扫码登录

### 2.2 拉代码

```bash
git clone https://github.com/caikenuan/zhiyue-campus-booking.git
cd zhiyue-campus-booking
git config user.name "史曼琪"
git config user.email "你的GitHub邮箱"
```

### 2.3 安装并启动

```bat
:: 第一次运行：下载便携版 MySQL、安装依赖、建库建表、写入演示数据
scripts\setup.bat

:: 启动后端（会自动拉起 MySQL）和管理端
scripts\start-all.bat
```

检查：

- <http://localhost:3000/api/health> 返回 `{"ok":true}`
- <http://localhost:5173> 能打开管理端登录页

### 2.4 小程序

1. 微信开发者工具 → 导入项目
2. 目录必须选到 `frontend\mini-program`（里面能直接看到 `app.js`、`app.json`、`pages`）
3. 详情 → 本地设置 → 勾选“不校验合法域名、web-view、TLS 版本以及 HTTPS 证书”
4. 编译后用学生账号登录

如果提示 AppID 无效：在导入时选择你自己的测试号，把新 AppID 写进本地 `frontend/mini-program/project.private.config.json`。这个文件已被 Git 忽略，**不要提交**。

## 3. 第二天：逐项验收你负责的模块

每验一项，在本文或 `docs/测试用例.md` 里记录：**操作步骤、实际结果、是否通过、截图文件名**。发现问题先记录，再修。

### 3.1 小程序端

- [ ] 扫码签到：进入签到页 → 扫码/手动输入签到码 → 预约变为“已签到”
- [ ] 预约详情页自助签到：开始前不能签到；开始后 15 分钟内可签到；超过 15 分钟提示已过期
- [ ] 已被自动释放的预约不能补签到，只能申诉
- [ ] 信用页：信用分、爽约次数、停权截止时间、信用记录显示正常
- [ ] 申诉：对已释放的预约提交申诉（理由至少 5 个字），提交后状态为待处理
- [ ] 普通学生看不到管理端入口

### 3.2 管理端（用 `admin / admin123` 和 `manager / manager123` 各验一遍）

- [ ] 仪表盘统计数字与数据库一致（今日预约、待签到、今日释放、启用场地、停权用户）
- [ ] 预约审批：列表筛选（状态、场地、日期）、详情、通过/驳回
- [ ] 辅助签到：未到开始时间不能签；开始后 15 分钟内可签；已释放的不能补签
- [ ] 用户与角色：只有学院管理员能进入；可改姓名、角色、启用/停用
- [ ] 爽约名单：只读，能看到爽约次数、信用分、停权截止日
- [ ] 利用率统计：按日期范围统计，数字与预约记录一致
- [ ] 操作日志：能看到签到、辅助签到、审批、申诉处理等操作，页面不提供修改/删除
- [ ] 申诉处理：学院管理员可通过/驳回；通过后对应爽约记录变为已撤销、信用分加回、停权解除（不足 3 次时）
- [ ] 场地管理员只能看到分配给自己的场地（种子数据里是 1—3 号场地），越界操作返回 403

### 3.3 权限与边界

- [ ] 学生调用 `/api/admin/dashboard` 返回 403
- [ ] 场地管理员操作未分配给自己的场地返回 403
- [ ] 非本人预约不能查看、取消或签到
- [ ] 重复取消、重复签到、已处理申诉再次处理都返回 409
- [ ] 维护时段内不能预约

## 6. 特别注意

1. **不要改业务规则**。以《业务规则卡确认单》为准：30 分钟粒度、单次最长 4 小时、允许首尾相接、只能约今天和明天、开始后 15 分钟未签到自动释放、近 30 天 3 次爽约停权 7 天。PPT 第 13 页的参数只是示例，不采用。
2. **不要提交敏感信息**：`.env`、真实数据库密码、密钥、AppID 私有配置、`node_modules`、`.tools` 都不要提交。仓库里的 `project.private.config.json` 已被忽略。
3. **不要提交课程 PPT、Word、PDF 原件**（根目录这些文件已被 `.gitignore` 忽略）。
4. **不要虚构结果**。没跑通就写没跑通，测试失败就记录失败原因，截图必须是真实运行画面。
5. **不要直接 push `main`**。走功能分支 + PR。
6. **测试会改数据库**。跑完破坏性测试后执行 `scripts\init-db.bat` 重置演示数据，再演示。
7. **时间相关测试**：只能预约今天和明天；签到窗口是开始后 0—15 分钟；定时任务每 30 秒执行一次，也可以由学院管理员调用 `POST /api/admin/scheduler/run` 手动触发。不要修改系统时间。
8. **端口冲突**：后端 3000、管理端 5173、MySQL 3306。端口被占用时先确认是不是本项目已经在运行，不要直接杀进程。
9. **路径**：小程序目录必须选到 `frontend\mini-program`；MySQL 便携版数据目录放在 `%USERPROFILE%\zhiyue-tools`（纯英文路径），不要放到中文目录。
10. **真机预览**：手机不能访问 `localhost`，要把小程序“我的 → 服务地址”改成电脑局域网 IP，例如 `http://192.168.1.10:3000/api`，并允许防火墙放行 3000 端口。
11. **公共文件少改**：`backend/src/config.js`、`database/schema.sql`、`backend/tests/core.test.js` 如果要改，先在群里说一声，避免和蔡珂暖冲突。
12. **答辩要能讲**：至少能讲清 `checkIn`、`releaseExpiredBookings`、`applySuspensionIfNeeded`、`handleAppeal` 四个函数的输入、边界和异常分支。
