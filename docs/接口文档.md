# 智约 · 接口文档

> 适用范围：`backend/` 当前实现（Express 4 + MySQL 8）。
> 默认地址：`http://localhost:3000/api`
> 最后核对：2026-11-25（接口实现与 `backend/src/routes/`、`backend/src/services/` 一致）

## 1. 通用约定

### 1.1 请求与响应

-   请求体与响应体均为 JSON，字符集 UTF-8；`Content-Type: application/json`。
-   除 `POST /api/auth/login` 和 `GET /api/health` 外，所有接口都需要登录。
-   登录后在请求头携带 JWT：

```http
Authorization: Bearer <token>
```

-   成功响应直接返回业务对象；列表统一放在 `items` 字段。
-   失败响应统一为：

```json
{
  "error": {
    "code": "SLOT_CONFLICT",
    "message": "该时段已被预约，请选择其他时段",
    "details": null
  }
}
```

-   时间字段统一为北京时间字符串：`YYYY-MM-DD HH:mm:ss`；请求中的预约时间接受 `YYYY-MM-DD HH:mm` 或 `YYYY-MM-DD HH:mm:ss`。
-   列表接口有固定上限（我的预约 100 条、管理端预约 200 条、日志最多 500 条），当前版本不分页。

### 1.2 角色与数据范围

| 角色 | 枚举值 | 数据范围 |
|---|---|---|
| 学生 | `STUDENT` | 只能查看/操作自己的预约、信用和申诉 |
| 场地管理员 | `VENUE_ADMIN` | 只能管理 `resource_managers` 表中分配给自己的场地及其预约 |
| 学院管理员 | `COLLEGE_ADMIN` | 全部场地、用户、预约、日志和统计 |

### 1.3 权限矩阵

| 接口组 | 未登录 | 学生 | 场地管理员 | 学院管理员 |
|---|---|---|---|---|
| `POST /api/auth/login`、`GET /api/health` | 允许 | 允许 | 允许 | 允许 |
| `GET /api/auth/me`、场地查询、空档查询、AI 找位 | 401 | 允许 | 允许 | 允许 |
| 我的预约、预约详情、二维码、创建/取消/续约、签到 | 401 | 仅本人预约 | 负责场地的预约（取消仅限本人/学院） | 全部 |
| 信用摘要、提交申诉 | 401 | 本人 | 本人 | 本人 |
| 管理端仪表盘、场地/预约/维护/申诉/日志/统计/爽约名单 | 401 | 403 | 负责场地范围 | 全部 |
| 管理端用户管理、场地新增/删除、管理员绑定、手动执行定时任务 | 401 | 403 | 403 | 允许 |

> 前端隐藏菜单只是体验优化，真正的权限判断在后端中间件和查询条件中完成；越权请求统一返回 `403 FORBIDDEN`。

### 1.4 业务规则（接口校验依据）

| 规则 | 取值 | 校验位置 |
|---|---|---|
| 预约粒度 | 30 分钟 | 起止时间的分钟数必须是 30 的整数倍，且秒数为 0 |
| 单笔最长 | 4 小时（240 分钟） | 创建预约、续约生成的新预约 |
| 预约窗口 | 今天和明天 | 按自然日判断，不能预约已经过去的时刻 |
| 跨天 | 不允许 | 开始与结束必须在同一天 |
| 相邻时段 | 允许首尾相接 | 冲突判定使用半开区间 `start < existing_end AND end > existing_start` |
| 未签到释放 | 开始后 15 分钟 | 后端定时任务每 30 秒扫描一次 |
| 爽约停权 | 近 30 天累计 3 次，停权 7 天 | 创建预约时拦截 |
| 维护时段 | 禁止预约 | 创建预约、空档查询同时校验 |

  "date": "2026-11-26",
  "openFrom": "08:00",
  "openTo": "22:00",
  "slots": [

      "end": "2026-11-26 08:30:00",

      "reason": null

    {

      "end": "2026-11-26 10:30:00",
      "startTime": "10:00",
      "endTime": "10:30",
      "available": false,
      "reason": "已被预约"

    {
      "start": "2026-11-26 08:00:00",

说明：

-   `slots` 按 30 分钟切分，`available=false` 的 `reason` 可能为 `场地未开放`、`维护时段`、`已被预约`、`已过时段`。

-   只统计状态为 `PENDING`、`CHECKED_IN` 的预约所占槽位；已取消、已释放、已完成的预约不占用。
-   错误：`400 VALIDATION_ERROR`（日期格式错误）、`404 NOT_FOUND`（场地不存在）。

## 4. 预约接口

### 4.1 创建预约

`POST /api/bookings` · 学生 / 管理员本人

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `resourceId` | body | integer | 是 | 场地 ID |
| `startAt` | body | string | 是 | 开始时间，`YYYY-MM-DD HH:mm`，须在 30 分钟网格上 |
| `endAt` | body | string | 是 | 结束时间，同一自然日，且晚于开始时间 |

请求示例：

```json
{
  "resourceId": 5,
  "startAt": "2026-11-26 20:00",
  "endAt": "2026-11-26 21:00"
}
```

响应 `201`：

```json
{
  "booking": {
    "id": 25,
    "userId": 3,
    "userName": "蔡珂暖",
    "studentNo": "2024030202003",
    "resourceId": 5,
    "resourceName": "活动室 D-301",
    "building": "学生中心",
    "room": "D-301",
    "resourceType": "ACTIVITY",
    "startAt": "2026-11-26 20:00:00",
    "endAt": "2026-11-26 21:00:00",
    "status": "PENDING",
    "source": "MINI_PROGRAM",
    "qrToken": "5e660765eb1a4f11a1f6bb7be8caf9ad",
    "checkedInAt": null,
    "cancelledAt": null,
    "cancelReason": null,
    "renewedFromId": null,
    "createdAt": "2026-11-25 20:03:24",
    "updatedAt": "2026-11-25 20:03:24"
  }
}
```

常见错误：

| HTTP | 错误码 | 触发条件 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 参数缺失、时间格式错误、结束早于开始 |
| 400 | `GRANULARITY_INVALID` | 起止时间不是 30 分钟整数倍（含秒数不为 0） |
| 400 | `DURATION_EXCEEDED` | 单笔超过 4 小时 |
| 400 | `CROSS_DAY_INVALID` | 开始与结束不在同一天 |
| 400 | `BOOKING_WINDOW_INVALID` | 已过时刻、不是今天/明天、超出场地开放时间 |
| 403 | `USER_SUSPENDED` | 近 30 天 3 次爽约，仍在停权期 |
| 403 | `FORBIDDEN` | 账号停用 |
| 404 | `NOT_FOUND` | 场地不存在 |
| 409 | `RESOURCE_CLOSED` | 场地状态不是 `OPEN` |
| 409 | `MAINTENANCE_WINDOW` | 所选时段与维护窗口重叠 |
| 409 | `SLOT_CONFLICT` | 时段已被占用，或并发抢单时唯一键冲突 |

### 4.2 续约

`POST /api/bookings/:id/renew` · 预约本人

续约不是修改原预约，而是**从原预约结束时刻开始生成一笔新的相邻预约**，新预约通过 `renewedFromId` 指向原预约；每笔仍单独受 4 小时上限约束。同一预约只能续约一次。

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | path | integer | 是 | 被续约的预约 ID |
| `newEndAt` | body | string | 是 | 新预约的结束时间，必须与原预约同一天 |

请求示例：

```json
{ "newEndAt": "2026-11-26 22:00" }
```

响应 `201`：`{ "booking": { ... } }`，新预约状态为 `PENDING`。

错误：除 4.1 的规则错误外，还可能返回 `403 FORBIDDEN`（非本人）、`404 NOT_FOUND`、`409 INVALID_STATE`（当前状态不能续约）、`409 CONFLICT`（已续约过）、`400 CROSS_DAY_INVALID`（跨天）。

## 5. 签到接口

### 5.1 扫码签到

`POST /api/bookings/checkin` · 预约本人

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `qrToken` | body | string | 是 | 预约详情里的签到码 |

请求示例：

```json
{ "qrToken": "5e660765eb1a4f11a1f6bb7be8caf9ad" }
```

响应 `200`：`{ "booking": { ... } }`，`status` 变为 `CHECKED_IN`，`checkedInAt` 写入时间。

错误：

| HTTP | 错误码 | 触发条件 |
|---|---|---|
| 404 | `INVALID_QR` | 签到码不存在 |
| 403 | `FORBIDDEN` | 不是本人预约 |
| 409 | `INVALID_STATE` | 未到开始时间、状态不是 `PENDING`、预约已释放 |
| 409 | `CHECKIN_EXPIRED` | 已超过开始后 15 分钟 |

### 5.2 按预约 ID 签到

`POST /api/bookings/:id/checkin` · 预约本人

无请求体，效果同 5.1，只是用预约 ID 代替签到码。错误同 5.1。

### 5.3 管理员辅助签到

`POST /api/admin/bookings/:id/assisted-checkin` · 场地管理员（限负责场地）/ 学院管理员

无请求体。写 `checkins` 记录（`method = 'ASSISTED'`），并在操作日志中记录 `BOOKING_ASSISTED_CHECKIN`。

响应 `200`：`{ "booking": { ... } }`。

错误：`403 FORBIDDEN`（越界场地）、`404 NOT_FOUND`、`409 INVALID_STATE`、`409 CHECKIN_EXPIRED`。

> 已被自动释放（`RELEASED`）的预约不能补记正常签到，只能由学生提交异常申诉。

## 6. 取消接口

### 6.1 取消预约

`POST /api/bookings/:id/cancel` · 预约本人 / 学院管理员

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | path | integer | 是 | 预约 ID |
| `reason` | body | string | 否 | 取消原因，最长 255 字符 |

请求示例：

```json
{ "reason": "临时有事" }
```

响应 `200`：

```json
{
  "booking": {
    "id": 25,
    "status": "CANCELLED",
    "cancelledAt": "2026-11-25 20:10:00",
    "cancelReason": "临时有事"
  }
}
```

取消成功后：

1. 预约状态置为 `CANCELLED`；
2. 删除该预约在 `booking_slots` 中的全部占用行，时段重新可约；
3. 写入 `operation_logs`（`BOOKING_CANCELLED`）。

错误：`403 FORBIDDEN`（非本人且非学院管理员、或场地管理员越界）、`404 NOT_FOUND`、`409 INVALID_STATE`（只有 `PENDING` 且尚未开始的预约可以取消；已开始需等待自动释放）。

### 7.2 利用率统计

`GET /api/admin/stats/utilization?from=YYYY-MM-DD&to=YYYY-MM-DD` · 管理端

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `from` | query | string | 否 | 开始日期，默认 6 天前 |
| `to` | query | string | 否 | 结束日期，默认今天；与 `from` 一起按自然日包含首尾两天 |

统计口径：只计入 `PENDING`、`CHECKED_IN`、`COMPLETED` 的预约；查询区间为 `[from 00:00, to+1 天 00:00)`，因此 `from=to=今天` 时 `days=1`；容量 = 场地每日开放分钟数 × 天数；利用率 = 已预约分钟 / 容量，保留 4 位小数。`from`/`to` 缺失、格式错误或 `from > to` 返回 `400 VALIDATION_ERROR`。

响应 `200`：

```json
{
  "from": "2026-11-19",
  "to": "2026-11-25",
  "items": [
    {
      "resourceId": 1,
      "resourceName": "研讨室 A-201",
      "type": "SEMINAR",
      "days": 7,
      "capacityMinutes": 5040,
      "bookedMinutes": 60,
      "bookingCount": 1,
      "utilizationRate": 0.0119
    }
  ]
}
```

### 7.5 管理端预约列表与审批

返回 `{ "items": [booking...] }`，字段同 3.4；按开始时间倒序，最多 200 条。

`POST /api/admin/bookings/:id/review` · 管理端

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `decision` | body | string | 是 | `APPROVE` 或 `REJECT` |
| `reason` | body | string | 否 | 审批意见，最长 255 字符 |

-   `APPROVE`：`PENDING_APPROVAL` → `PENDING`，写 `BOOKING_APPROVED` 日志。
-   `REJECT`：`PENDING_APPROVAL` → `REJECTED`，删除占用槽位，写 `BOOKING_REJECTED` 日志。

响应 `200`：`{ "booking": { ... } }`。错误：`403 FORBIDDEN`、`404 NOT_FOUND`、`409 INVALID_STATE`（不是待审批状态）。

### 8.2 提交申诉

`POST /api/credit/appeals` · 学生本人

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `bookingId` | body | integer | 是 | 已释放（`RELEASED`）的预约 ID |
| `reason` | body | string | 是 | 申诉理由，5—1000 字 |

响应 `201`：

```json
{ "appeal": { "id": 1, "bookingId": 12, "status": "PENDING" } }
```

错误：`403 FORBIDDEN`（不是自己的预约）、`404 NOT_FOUND`、`409 INVALID_STATE`（预约不是 `RELEASED`）、`409 CONFLICT`（已有待处理申诉）。

### 8.3 申诉列表与处理

-   `GET /api/credit/appeals`：学生看自己的；场地管理员看负责场地；学院管理员看全部。
-   `GET /api/admin/appeals`：管理端申诉列表。
-   `POST /api/admin/appeals/:id/handle`：`{ "decision": "APPROVED" | "REJECTED", "result": "说明" }`。

申诉通过时，在同一事务内撤销对应爽约记录、信用分 +10（上限 100）；若近 30 天有效爽约记录不足 3 次，则解除停权。

### 8.4 AI 找位

`POST /api/ai/find-seat` · 登录用户

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `message` | body | string | 是 | 自然语言需求，2—500 字 |

请求示例：

```json
{ "message": "明天下午3点，4个人，找个研讨室开1小时" }
```

响应 `200`：

```json
{
  "interpretation": {
    "date": "2026-11-26",
    "startTime": "15:00",
    "durationMinutes": 60,
    "people": 4,
    "resourceType": "SEMINAR",
    "preference": "明天下午3点，4个人，找个研讨室开1小时"
  },
  "candidates": [
    {
      "resourceId": 1,
      "resourceName": "研讨室 A-201",
      "type": "SEMINAR",
      "typeLabel": "研讨室",
      "building": "图书馆",
      "room": "A-201",
      "capacity": 8,
      "startAt": "2026-11-26 15:00:00",
      "endAt": "2026-11-26 16:00:00",
      "startTime": "15:00",
      "endTime": "16:00",
      "reason": "研讨室，可容纳 8 人，15:00-16:00 空闲",
      "score": 122
    }
  ],
  "source": "rule",
  "fallback": true
}
```

说明：

-   配置了 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL` 时优先调用大模型解析意图（`source = "llm"`）；未配置、超时或解析失败时回退内置中文规则（`source = "rule"`, `fallback = true`）。
-   大模型只负责把自然语言解析成 `{date, startTime, durationMinutes, people, resourceType}`，**是否空闲永远由数据库实时查询决定**，最多返回 3 个候选。
-   没有候选时返回 `note` 提示换时间或场地类型。

### 8.5 图片上传

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `POST` | `/api/uploads` | 已登录 | 上传场地图片或签到照片，`multipart/form-data`，字段名 `file` |

限制：

-   仅 `image/jpeg`、`image/png`、`image/webp`、`image/gif`；
-   单张 ≤ 5 MB；
-   后端统一上传，前端不接触对象存储密钥；
-   数据库只保存返回的 URL（`resources.image_url`、`checkins.photo_url`），不保存二进制。

成功响应 `201`：

```json
{
  "url": "https://zhiyue.example.com/uploads/images/2026/11/6f1c....png",
  "key": "images/2026/11/6f1c....png",
  "driver": "local",
  "contentType": "image/png",
  "size": 70
}
```

`driver` 为 `local`（服务器数据卷）或 `s3`（S3 兼容对象存储）。失败：未登录 `401 UNAUTHORIZED`；类型或大小不符 `400 VALIDATION_ERROR`。

```bash
TOKEN=$(curl -s -X POST http://localhost:3000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"studentNo":"admin","password":"admin123"}' | jq -r .token)

curl -X POST http://localhost:3000/api/uploads \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@room.png;type=image/png"
```

签到接口可带可选字段 `photoUrl`（先调上传接口拿到 URL）：

```json
POST /api/bookings/12/checkin
{ "photoUrl": "https://zhiyue.example.com/uploads/images/2026/11/6f1c....png" }
```

## 10. 错误码表

| 错误码 | 典型 HTTP | 含义 | 客户端处理建议 |
|---|---|---|---|
| `VALIDATION_ERROR` | 400 | 参数不合法，`details` 给出字段级原因 | 提示具体字段 |
| `GRANULARITY_INVALID` | 400 | 时间不是 30 分钟整数倍 | 引导重新选择时段 |
| `DURATION_EXCEEDED` | 400 | 单笔超过 4 小时 | 提示拆分或缩短 |
| `BOOKING_WINDOW_INVALID` | 400 | 已过时刻、非今日/明日、超出开放时间 | 刷新可选时段 |
| `CROSS_DAY_INVALID` | 400 | 跨天预约/续约 | 改为同一天 |
| `UNAUTHORIZED` | 401 | 未登录或 JWT 过期 | 清除 token，回登录页 |
| `FORBIDDEN` | 403 | 角色或数据范围不允许 | 隐藏无权入口，提示无权限 |
| `USER_SUSPENDED` | 403 | 爽约停权中 | 显示停权截止时间和申诉入口 |
| `NOT_FOUND` | 404 | 资源/预约/申诉不存在 | 刷新列表或返回上一页 |
| `INVALID_QR` | 404 | 签到码无效 | 提示重新扫码 |
| `CONFLICT` | 409 | 通用冲突（重复申诉、已续约、场地有预约不能删等） | 展示具体 `message` |
| `SLOT_CONFLICT` | 409 | 时段已被占用（含并发抢单） | 刷新空档后重选 |
| `MAINTENANCE_WINDOW` | 409 | 与维护窗口重叠 | 显示维护时段 |
| `RESOURCE_CLOSED` | 409 | 场地未开放 | 推荐其它场地 |
| `INVALID_STATE` | 409 | 当前状态不允许该操作 | 刷新详情后重试 |
| `CHECKIN_EXPIRED` | 409 | 超过开始后 15 分钟 | 提示走异常申诉 |
| `INTERNAL_ERROR` | 500 | 未捕获的服务端错误 | 提示稍后重试，并查看后端日志 |

健康检查 `GET /api/health` 在数据库不可用时返回 HTTP 503 和 `{ "ok": false, "error": "数据库未连接" }`，不属于统一错误包络。

> **与《需求说明书》的差异说明**：需求文档 C-04 曾使用错误码名 `WINDOW_EXCEEDED`，最终实现统一为 `BOOKING_WINDOW_INVALID`；需求文档中“在预约表对（场地编号、开始时间、状态）建唯一约束”的草案，最终改为按 30 分钟槽位建 `booking_slots(resource_id, slot_start)` 唯一主键，因为前者只能锁开始时间、无法防住跨时段重叠。业务规则本身（30 分钟粒度、4 小时上限、1 天窗口、相邻可首尾相接）没有变化。

## 11. 状态与枚举

### 11.1 预约状态 `bookings.status`

| 值 | 含义 | 可执行操作 |
|---|---|---|
| `PENDING` | 待签到 | 签到、取消、续约 |
| `CHECKED_IN` | 已签到 | 到期自动完成、续约 |
| `COMPLETED` | 已完成 | 只读 |
| `CANCELLED` | 用户/管理员取消 | 只读 |
| `RELEASED` | 超时未签到被系统释放 | 可提交申诉 |
| `PENDING_APPROVAL` | 待管理员审批 | 管理员通过/驳回 |
| `REJECTED` | 审批驳回 | 只读 |

## 12. 调用示例（curl）

```bash
# 1. 登录并取 token
TOKEN=$(curl -s -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"studentNo":"2024030202003","password":"123456"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['token'])")

# 2. 查明天场地 1 的空档
curl "http://localhost:3000/api/resources/1/availability?date=2026-11-26" \
  -H "Authorization: Bearer $TOKEN"

# 3. 创建预约
curl -X POST http://localhost:3000/api/bookings \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"resourceId":5,"startAt":"2026-11-26 20:00","endAt":"2026-11-26 21:00"}'

# 4. 取消预约
curl -X POST http://localhost:3000/api/bookings/25/cancel \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"reason":"临时有事"}'

# 5. 学院管理员查看利用率
ADMIN=$(curl -s -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"studentNo":"admin","password":"admin123"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['token'])")
curl "http://localhost:3000/api/admin/stats/utilization?from=2026-11-19&to=2026-11-25" \
  -H "Authorization: Bearer $ADMIN"
```
