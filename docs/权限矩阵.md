# 智约 · 权限矩阵

> 版本：S2 验收版（2026-11-22）
> 适用：学生端、管理端、后端 API
> 角色：`STUDENT`（学生）、`VENUE_ADMIN`（场地管理员）、`COLLEGE_ADMIN`（学院管理员）
> 数据范围依据：`backend/src/services/availability.js#getManagedResourceIds`、`booking.js#assertBookingAccess`、`admin.js#assertResourceScope`、`scopeResourceIds`、`credit.js#listAppeals/listNoShows/getUtilization`

## 1. 角色与数据范围

| 角色 | 数据范围 | 典型账号 |
|---|---|---|
| 未登录 | 只能访问 `POST /api/auth/login`、`GET /api/health` | — |
| 学生 `STUDENT` | 只能查看/操作**本人**预约、本人信用、本人申诉 | 2024030202003 / 123456 |
| 场地管理员 `VENUE_ADMIN` | `resource_managers` 分配给自己的场地（种子数据为 1—3 号）及其预约、申诉、日志、统计 | manager / manager123 |
| 学院管理员 `COLLEGE_ADMIN` | 全部场地、全部预约、全部用户、全部日志、申诉、统计 | admin / admin123 |

> 重要：停权（`suspended_until`）是账号级状态，不绑定场地；场地管理员仪表盘里的“停权用户”是全局计数，其余统计按负责场地过滤。

## 4. 权限判定顺序与错误码

后端按以下顺序判定，命中即返回：

1. 无 token / token 无效 → **401 `UNAUTHORIZED`**
2. 账号 `status != 'ACTIVE'` → **403 `FORBIDDEN`**
3. 路由角色不匹配（`requireRole`）→ **403 `FORBIDDEN`**
4. 预约归属/场地范围不匹配（`assertBookingAccess`、`assertResourceScope`、`assertCheckInPermission`）→ **403 `FORBIDDEN`**
5. 预约不存在 → **404 `NOT_FOUND` / `INVALID_QR`**
6. 状态/时间不允许 → **409 `INVALID_STATE` / `CHECKIN_EXPIRED` / `USER_SUSPENDED`**

常见细节：

- 学生查别人预约：`GET /bookings/:id` → 403，不是 404（避免泄露是否存在）。
- 场地管理员查未分配场地预约：403。
- 场地管理员查 `?resourceId=6` 的列表：返回空数组，不报 403（列表筛选语义）。
- 场地管理员修改未分配场地、维护时段：403。
- 场地管理员处理未分配场地的申诉：403。
- 场地管理员访问用户管理：403；前端还会跳回仪表盘。
- 已处理申诉再次处理：409 `INVALID_STATE`。
- 重复取消/重复签到：409 `INVALID_STATE`。
- 停权用户下单：403 `USER_SUSPENDED`，但登录、查看信用、提交申诉不受影响。
